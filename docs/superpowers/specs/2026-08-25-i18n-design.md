# Интернационализация лендинга Ecru

Дата: 2026-08-25
Статус: дизайн утверждён, план реализации не написан

## Цель

Отдавать лендинг на нескольких языках, каждый по своему URL, не заводя
фреймворк и не теряя обещание страницы: ни одного внешнего запроса, ни
одного трекера, ни одного байта JS сверх нужного.

Сейчас: `en`, `uk`. Позже: `pl`, `de`.

## Почему не React

React решает синхронизацию сложного состояния с DOM. На этой странице
состояния нет — текст, картинки и одна форма на `fetch`. Переход стоил бы
переписывания 582 строк разметки и 900 строк CSS, привёл бы `node_modules`
в рантайм и положил бы бандл на страницу, которая продаёт «никакого
сервера, никакого аккаунта, всё локально». Чтобы не потерять индексацию,
пришлось бы всё равно генерировать статику — то есть прийти туда же, куда
приходит план ниже, только дороже.

i18n — повод завести один источник строк и один шаг сборки, а не сменить
фреймворк.

## Решения

| Вопрос | Решение |
| --- | --- |
| Где живут строки | `i18n/<lang>.json`, по ключу на строку |
| Как собирается страница | `build.js`, Node, ноль зависимостей, подстановка `{{ключ}}` |
| URL | `en` в корне, остальные в `/<lang>/` |
| Определение языка | Только по URL. Никакого редиректа по `navigator.language` |
| Переключатель | Четыре ссылки в шапке, текущая — `aria-current="page"` |
| Якоря секций | Остаются английскими на всех языках |
| Строки внутри JS | `data-msg-*` на форме, как существующий `data-endpoint` |
| Кириллица в заголовках | IBM Plex Serif, подключён по `unicode-range` |

## Структура файлов

    src/index.html          шаблон: разметка с {{ключами}} вместо прозы
    i18n/en.json            ~130 строк
    i18n/uk.json
    build.js                ~80 строк
    style.css               меняется только блок @font-face (см. «Шрифт»)
    waitlist.js             меняется: литералы -> form.dataset
    dist/                   результат сборки, в .gitignore, не коммитится
      index.html              en
      uk/index.html
      style.css, waitlist.js, assets/   скопированы как есть

`index.html` в корне репозитория исчезает, его место занимает `src/index.html`.

## Формат шаблона и словарей

Шаблон не парсится как HTML. `build.js` делает одну текстовую замену по
`/\{\{([\w.@]+)\}\}/g`. Поэтому вложенная разметка внутри строки — не
особый случай: значение хранится в JSON вместе с тегами и подставляется
целиком.

Шаблон:

    <h1 class="display hero__title">{{hero.title}}</h1>
    <p class="lede hero__lede">{{hero.lede}}</p>

`i18n/en.json`:

    {
      "hero.title": "Your whole wardrobe, and a straight answer about it.",
      "hero.lede": "Ecru catalogues what you own, builds outfits from it, and remembers what you wore. Every time it says two things go together, it tells you <em>why</em> — in one sentence."
    }

Значения вставляются дословно, без экранирования: разметка внутри них —
намеренная часть текста, а содержимое файлов наше собственное.

Ключи именуются по месту в странице (`hero.`, `shoot.`, `wedge.`, `faq.`,
`footer.`), чтобы шаблон читался как оглавление. Это компенсирует главную
цену подхода: `src/index.html` больше не читается как страница, и чтобы
прочитать секцию, нужны шаблон и `en.json` рядом.

## Контракт build.js

1. Читает `src/index.html` и каждый `i18n/*.json`.
2. Для каждого языка подставляет строки и служебные значения `@`-ключей.
3. Пишет `dist/index.html` для языка по умолчанию (`en`) и
   `dist/<lang>/index.html` для остальных.
4. Копирует `style.css`, `waitlist.js`, `assets/` в `dist/`.
5. Копирует `.nojekyll` в `dist/`. Через `upload-pages-artifact` Jekyll и
   так не запускается, но файл лежит в репозитории намеренно, и терять его
   при смене способа деплоя не стоит.
6. **Падает с ненулевым кодом**, если:
   - ключ есть в шаблоне и отсутствует в каком-либо языке;
   - ключ есть в словаре и не используется в шаблоне;
   - словарь не парсится.

Список языков и язык по умолчанию объявлены одной константой в начале
`build.js`. Добавить язык — значит дописать код в этот список и положить
рядом `i18n/<lang>.json`; всё остальное (папка, `hreflang`, переключатель)
выводится из него.

Шестой пункт — единственное, что удерживает четыре языка от расхождения.
Сборка должна ломаться громко, а не выпускать страницу с `{{faq.cost}}` в
вёрстке.

Служебные `@`-ключи, которые заполняет сборка, а не переводчик:

| Ключ | Значение |
| --- | --- |
| `{{@lang}}` | Код языка для `<html lang>` |
| `{{@base}}` | `` для корня, `../` для языковой папки |
| `{{@alternates}}` | Блок `<link rel="alternate" hreflang>` на все языки плюс `x-default` |
| `{{@canonical}}` | Канонический URL страницы |
| `{{@langswitch}}` | Разметка переключателя языков |

## Пути

Все пути в разметке относительные — README объясняет почему: сайт отдаётся
из `/ecru-landing/`, не с корня домена. Из `dist/uk/index.html` такие пути
искали бы `/ecru-landing/uk/assets/…` и не нашли бы ничего.

Поэтому в шаблоне каждый путь получает префикс `{{@base}}`:

    <link rel="stylesheet" href="{{@base}}style.css" />
    <img src="{{@base}}assets/shots/pairs.jpg" …>

`style.css` не трогаем: пути к шрифтам внутри него считаются от самого
CSS-файла, который лежит в корне `dist/`, и работают для обеих страниц как
есть.

Следствие, которое стоит сохранить: относительные пути означают, что
`dist/uk/index.html` открывается двойным кликом через `file://` и
выглядит корректно. Локальный сервер не нужен ни для одного языка.

## Метаданные и hreflang

Каждая страница получает:

- `<html lang="{{@lang}}">`;
- переведённые `<title>` и `<meta name="description">`;
- `<link rel="canonical">` на себя;
- полный блок `<link rel="alternate" hreflang>` на все языки, включая себя,
  плюс `x-default` на английскую версию.

Блок генерируется сборкой из списка языков. Руками он не поддерживается:
при четырёх языках это шестнадцать строк, которые разъедутся при первом же
добавлении пятого.

## Переключатель языков

Ссылка на язык в шапке рядом с навигацией, текущая помечена
`aria-current="page"` и ссылкой не является. Сейчас ссылок две, после
добавления `pl` и `de` — четыре. Список плоский, не выпадающий: на таком
количестве языков выпадающий не нужен.

Переключателя нет ни на одном артборде канваса «Ecru Landing». По README
канвас — источник правды, поэтому это **третье сознательное отступление от
макета**, и оно дописывается в тот же список в README рядом с датой запуска
в FAQ и дисклеймером про имя.

## Строки внутри waitlist.js

В `waitlist.js` пять сообщений: невалидный адрес, неподключённый endpoint,
«Sending…», успех, ошибка. Отдельного словаря для JS не заводим — в файле
уже есть подходящая идиома, `form.dataset.endpoint`.

Каждая форма получает пять атрибутов из того же JSON:

    <form class="waitlist" data-endpoint=""
          data-msg-invalid="{{form.invalid}}"
          data-msg-unwired="{{form.unwired}}"
          data-msg-sending="{{form.sending}}"
          data-msg-ok="{{form.ok}}"
          data-msg-fail="{{form.fail}}" novalidate>

`waitlist.js` читает `form.dataset.msgInvalid` вместо литерала. Скрипт
становится языконезависимым: ни словаря, ни определения языка, ни файла на
язык. Все тексты страницы остаются ровно в одном месте.

Форм на странице две, атрибуты у них одинаковые. Дублирование в выводе
осознанное — альтернатива требует логики.

## Шрифт: кириллица в заголовках

`style.css:110` объявляет Instrument Serif только в сабсетах `latin` и
`latin-ext`, и комментарий там же говорит прямо: «тільки латиниця». Это не
упущение — у Instrument Serif кириллицы нет вовсе, дорезать нечего. Без
вмешательства все заголовки на украинской странице (`h1`, все `h2`,
вордмарк в шапке и подвале, `h3` в манифесте) упали бы в фолбэк
`'Iowan Old Style', Georgia, serif` — то есть титульное лицо страницы стало
бы чужим.

Решение: **IBM Plex Serif для кириллического диапазона.** Семейство Plex
уже на странице (Sans и Mono), так что шрифтовая система остаётся одной.

Область: только кириллица. Instrument Serif остаётся заголовочным шрифтом
латиницы, и страницы `en`, `pl`, `de` не меняются ни на пиксель. Достигается
тем же приёмом, что уже используется для Plex Sans — `unicode-range`:

    @font-face {
      font-family: 'Ecru Display Cyrillic';
      font-style: normal;
      font-weight: 400;
      font-display: swap;
      src: url('assets/fonts/ibm-plex-serif-400-cyrillic.woff2') format('woff2');
      unicode-range: U+0301, U+0400-045F, U+0490-0491, U+04B0-04B1, U+2116;
    }

и добавлением семейства в стек `--display` (`style.css:174`) после
Instrument Serif.

`.display` использует только начертание 400 и не использует курсив
(`style.css:295`), поэтому файл нужен ровно один. Лицензия покрыта уже
лежащим `assets/fonts/ibm-plex-OFL.txt` — Plex Serif под тем же OFL.

Метрики двух гарнитур не совпадают: Plex Serif шире, ниже по контрасту и
имеет больший x-height, поэтому на одном и том же `font-size` украинские
заголовки будут выглядеть крупнее и плотнее. `line-height: 1.06` и
`letter-spacing: -0.01em` в `.display` подобраны под Instrument Serif.
Ожидаемо потребуется поправка, ограниченная `:lang(uk)`; её величина
определяется глазами на обеих ширинах артборда, а не заранее.

## Строки, которые нельзя переводить

Часть текста страницы — дословные цитаты из интерфейса приложения:

- объяснения в карточке причин (`index.html:186-189`);
- вердикты примерочной (`index.html:388-390`);
- названия экранов и подписи внутри `alt`-текстов, например
  «What to wear it with» (`index.html:70`).

Если перевести их с английского, украинская страница покажет фразы,
которых в украинском приложении нет — то есть соврёт о продукте ровно в том
месте, где показывает продукт. Такие ключи помечаются в словаре префиксом
`quote.` и берутся из локали приложения, а не переводятся. Их около
пятнадцати.

## Объём работы по тексту

Около 130 строк на язык: 29 заголовков, 55 абзацев (включая 13 надзаголовков
и два `fineprint`), 16 пунктов списков, 8 `dt`/`dd` полосы доверия,
10 `alt`-текстов, 4 ссылки навигации, `title`, `description`, два
`aria-label`, подпись и плейсхолдер формы, пять сообщений формы.

`alt`-тексты — не подписи, а содержательное описание скриншотов; переводятся
полностью и на общих основаниях.

## Проверки перед выпуском

Для каждого языка:

1. `node build.js` завершается с кодом 0.
2. В `dist/**/*.html` нет вхождений `{{`.
3. Страница открывается через `file://` из своей папки: стили, шрифты и все
   десять скриншотов на месте.
4. Заголовки набраны нужной гарнитурой, не фолбэком (для `uk` — проверить
   отдельно, это смысл всей работы со шрифтом).
5. Вёрстка просмотрена глазами на 1440 и 390 — ширинах артбордов канваса.
   Длина текста меняется от языка к языку, а вся вёрстка `clamp()`-натянута
   между этими двумя состояниями. Пункт повторяется для каждого нового языка,
   это не разовая проверка.
6. Кавычки соответствуют языку: « » для украинского, „ “ для немецкого.
7. Форма показывает переведённые сообщения во всех пяти состояниях.
8. `hreflang` ссылается на существующие URL во все стороны.

## Вне рамок

- **Редирект по `navigator.language`.** Ломает индексацию и запирает
  человека, пришедшего по ссылке на конкретную версию.
- **Сохранение якоря при переключении языка.** Со `#limits` на `/uk/`
  человек попадёт в начало английской страницы. Лечится тремя строками JS,
  но это первый шаг к роутеру на статической странице. Добавляется, если
  кто-то пожалуется.
- **Перевод самого приложения.** Отдельная работа в другом репозитории.
- **Локализация чисел и дат.** На странице их нет: количества написаны
  словами («about ninety seconds», «forty pieces»), а даты запуска пока не
  существует.

## Открытый вопрос

Полоса доверия обещает приложение на четырёх языках — «Ukrainian, English,
Polish, Spanish» (`index.html:87`), подвал повторяет тот же список. Это
языки приложения, не сайта. Немецкая версия лендинга будет рекламировать
приложение без немецкого интерфейса: читатель дойдёт до полосы доверия и
увидит, что его языка в списке нет.

Развилка — на момент добавления `de`, не сейчас: немецкий появляется в
приложении, либо лендинг ограничивается `uk`/`en`/`pl`, либо немецкая
страница честно называет языки интерфейса. Выпуску `en` + `uk` это не
мешает. Ключ полосы держим отдельным, чтобы текст можно было менять по
языкам.
