# Конфігурація PostHog (знята з лендінгу, зберігається для застосунку)

Лендінг більше не має аналітики: `analytics.js` видалено, сторінки нічого
нікуди не шлють. Цей файл — не інструкція для сайту, а протокол того, що
саме тут працювало, щоб ті самі рішення не довелося відновлювати з нуля,
коли PostHog під'єднуватимуть у мобільному застосунку.

## Проєкт

| | |
|---|---|
| Ключ проєкту | `phc_xUirmvmPzqhCLjv9J9cjDGTxwjDgdUVESorqD3kSXY4m` |
| Регіон / `api_host` | `https://eu.i.posthog.com` (EU, дані лежать у Європі) |
| Хост статики | `https://eu-assets.i.posthog.com` — це `api_host` із `.i` → `-assets.i` |

Ключ проєкту публічний за задумом: ним можна тільки писати події — читати,
робити запити чи видаляти ним не можна. Тому він лежав просто в репозиторії,
а не в секретах. Для застосунку це означає те саме: ключ можна тримати в
`app.config.js` / `extra`, окремий секрет під нього заводити не треба.

Проєкт EU-шний, тож і в застосунку `host` має бути `https://eu.i.posthog.com`.
Дефолтний `us.i.posthog.com` із цим ключем просто не працюватиме.

## Налаштування ініціалізації і чому саме такі

```js
posthog.init(KEY, {
  api_host: 'https://eu.i.posthog.com',
  persistence: 'memory',
  person_profiles: 'identified_only',
  disable_external_dependency_loading: true,
  disable_surveys: true,
  capture_performance: false,
});
```

- **`persistence: 'memory'`** — ні куків, ні `localStorage`. Підвал сайту
  обіцяв відвідувачу, що сторінка не ставить стежних куків, і обіцянка мала
  лишатися правдою; побічно це знімало потребу в банері згоди в ЄС. Ціна:
  кожне завантаження сторінки PostHog бачить як нову людину, тож «унікальні»
  там рахували візити, а не людей.
  **У застосунку це рішення радше не переносити:** там немає ні банера, ні
  куків, а стабільний анонімний `distinct_id` між запусками — єдиний спосіб
  відрізнити повернення від першого запуску. Тобто в мобілці — звичайне
  сховище (AsyncStorage), а не `memory`.
- **`person_profiles: 'identified_only'`** — профіль людини заводиться лише
  після `identify`. На сайті `identify` не викликав ніхто (форми пошти там
  уже не було), тож профілів не з'являлося взагалі: лишалися безіменні
  події. Для застосунку без акаунтів це правильний дефолт, його варто
  лишити — Ecru не має логіну, ідентифікувати нема кого й нічим.
- **`disable_external_dependency_loading: true`**, **`disable_surveys: true`**,
  **`capture_performance: false`** — це суто веб-історія: `array.js` за
  замовчуванням дотягує з мережі опитування, «мертві кліки» й web vitals.
  Сторінка ними не користувалася, а решта всього на лендінгу лежала локально,
  тож це були три зайві запити до чужого домену. У React Native відповідників
  цих прапорців здебільшого немає — там натомість вирішувати треба про
  `captureAppLifecycleEvents`, `captureScreenViews`, `sessionReplay` і
  `autocapture`.

## Що саме вимірювалося

- **`$pageview`** — перегляди, `array.js` рахував сам, дротити нічого не
  треба було.
- **`$autocapture`** — кліки, теж автоматично: одна подія на клік із
  CSS-селектором елемента.
- **`store_click`** — єдина подія, знята руками. Властивості: `place`
  (`hero` або `finale` — котра з двох кнопок App Store) і `lang` (мова
  сторінки). Існувала тому, що кнопка магазину була єдиною конверсією
  сторінки, а будувати воронку з `$autocapture` означає щоразу фільтрувати
  по класу.

Кнопки несли `data-place="hero"` і `data-place="finale"` — рівно для цієї
події, більше цей атрибут ніде не читався. Разом з аналітикою прибрано і його.

## Дві дрібниці, які варто пам'ятати

- **`transport: 'sendBeacon'`** для `store_click`: клік вів на apple.com, тож
  сторінка от-от зникала разом зі своїми запитами в польоті. Маячок браузер
  досилає вже після навігації. Без цього саме конверсія губилася б найчастіше.
  У застосунку цієї проблеми немає — екран нікуди не зникає.
- **Черга подій.** Замість офіційного мініфікованого сніпета стояв звичайний
  `<script>`. Сніпет заводить чергу, щоб події, зняті до завантаження
  `array.js`, не губились; тут та черга була майже ні до чого, і ціною була
  втрата кліку в першу пів секунди. У `posthog-react-native` черга є з
  коробки, тож цей компроміс у мобілці не відтворюється.
